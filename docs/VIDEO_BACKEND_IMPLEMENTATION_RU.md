# Подключение реальной генерации видео в Kolzai

Этот документ переводит требования из VIDEO_GENERATION_10S_RU.md в конкретный backend-контракт. Сейчас Android-кнопка генерации отключена, а реальный видеопровайдер не подключён. Не показывать фиктивный прогресс и не выдавать демонстрационный файл за сгенерированный.

## Почему нужен backend

Ключ видеопровайдера нельзя помещать в APK: приложение можно декомпилировать. Все вызовы провайдера, проверка тарифов, лимиты, хранение job ID и выдача результата выполняются на сервере. Android знает только URL собственного backend и пользовательскую авторизацию.

## Первый вертикальный срез

1. Развернуть HTTPS backend с endpoint-ами ниже.
2. Подключить один видеопровайдер, который на момент интеграции официально поддерживает text-to-video и длительность 10 секунд либо больше.
3. Сохранить ключ в secret manager хостинга.
4. Проверить генерацию одним тестовым пользователем.
5. Подключить Android к backend и проверить реальный MP4 на физическом устройстве.
6. Только после этого включить кнопку в релизной сборке.

## API

### Создать задачу

`POST /v1/video/jobs`

Заголовки: `Authorization: Bearer <user-token>`, `Content-Type: application/json`.

Тело:
```json
{
  "prompt": "A red robot walks through a bright workshop and waves at the camera.",
  "duration_seconds": 10,
  "aspect_ratio": "16:9",
  "resolution": "720p"
}
```

Ответ HTTP 202:
```json
{
  "job_id": "opaque-id",
  "status": "queued",
  "requested_duration_seconds": 10
}
```

Сервер валидирует длину промпта, длительность, формат, доступность провайдера, права пользователя и лимиты до списания средств/квоты. Не принимать provider model ID или API key от клиента.

### Проверить задачу

`GET /v1/video/jobs/{job_id}`

Ответ:
```json
{
  "job_id": "opaque-id",
  "status": "processing",
  "progress": 45,
  "result": null,
  "error": null
}
```

Допустимые статусы: queued, submitting, processing, finalizing, completed, failed, cancelled. progress — необязательное целое 0–100, только если провайдер действительно предоставляет достоверный прогресс.

Завершённая задача:
```json
{
  "job_id": "opaque-id",
  "status": "completed",
  "progress": 100,
  "result": {
    "url": "https://temporary.example/video.mp4",
    "duration_seconds": 10,
    "content_type": "video/mp4"
  },
  "error": null
}
```

URL результата должен быть короткоживущим и доступным только владельцу задачи. В production не использовать example-домен из этого документа.

### Отмена

`DELETE /v1/video/jobs/{job_id}`

Отмена идемпотентна. Если провайдер уже не может отменить рендер, вернуть фактический статус, а не заявлять, что задача остановлена.

## Хранение и безопасность

- Таблица jobs: внутренний ID, user ID, provider, provider job ID, status, параметры, timestamps, error code.
- Не логировать токены, API keys, полные приватные URL и пользовательские изображения.
- Проверять владение job ID на каждом GET/DELETE.
- Ограничить размер запроса и частоту создания задач.
- Установить timeout, retry только для безопасных операций и защиту от повторного списания квоты.
- Не считать клиентское поле progress источником истины.
- Для изображений использовать приватное хранилище и короткоживущие ссылки.

## Android-поведение

- Кнопка включается только при наличии корректного HTTPS backend URL и успешной проверки доступности backend.
- После POST сохранить job ID локально, чтобы пережить закрытие приложения.
- Опрос статуса выполнять с увеличивающимся интервалом и прекращать при terminal status.
- Не опрашивать бесконечно: ограничить время и показать кнопку повтора/обновления.
- Открывать результат только после completed и проверки content type.
- При 401 попросить повторную авторизацию; при 429 показать ограничение; при 5xx — понятную ошибку и безопасный повтор.
- Если backend не настроен, показывать «Сервер генерации не подключён», не имитировать создание.

## Приёмочные проверки

- Длительность 10 секунд подтверждена метаданными реального файла, а не только запросом.
- MP4 скачивается/открывается на Android, длительность и ориентация корректны.
- Чужой job ID недоступен.
- Повтор POST не создаёт неожиданные платные дубликаты.
- Проверены отмена, тайм-аут, ошибка провайдера, 429 и перезапуск приложения.
- В APK и Git нет секретов провайдера.
